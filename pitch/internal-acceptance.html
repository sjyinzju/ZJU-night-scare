01 · PROJECT BRIEF

项目简介

把校园怪谈转化为可行走、可调查、可选择的互动体验。
真实校园逐渐变成心理迷宫，熟悉的道路、宿舍、湖面与教学楼开始出现偏差。

《浙大夜惊魂》从农医馆的异常借阅记录展开。玩家离开图书馆后进入紫金港外景，沿道路前往白沙宿舍、临湖餐厅、医学院、启真湖与小剧场。调查获得的证据、人物关系、角色属性和关键道具，会共同影响终章判断。

项目重点：完成一条从开场调查、校园移动、建筑探索到多结局收束的核心游玩流程，并让团队成员能够解释功能与实现方式。

03 · SCENE DIRECTION

校园空间与氛围设计

惊悚感来自熟悉空间中的轻微偏差，环境会随着剧情阶段逐渐失真。

农医馆

故事开端 / 秩序裂缝

冷静、安静、档案感明确。手电、笔记本、小票、符咒、异常书架和灯下人物组成第一条调查链。

医学院

全图视觉核心

六楼冷窗、病床、巡查守则、车库封印与地下仓库逐层加深压力，承担主线证据的集中揭示。

白沙学园

日常生活崩坏

围绕 2 幢 123 室与 3 幢 216 室展开，房间调查、论坛信息和真假出口把生活空间转化为追逐场。

启真湖

记忆污染地点

保持可辨识的蓝色水面，通过低雾、错位倒影、延迟倒影与水草黑线表达记忆和现实的偏移。

西区沼泽与小剧场

异空间 / 终章入口

沼泽提供校园秩序外的迷失感；小剧场以旧海报、唱段、后台镜面和胶片放映完成故事收束。

现实偏移系统玩家接近关键区域时，雾、灯光、标签、时间和局部异常会同步变化；五个剧情阶段拥有不同的基础失真强度。
04 · GAME SYSTEMS

核心游戏系统

18 项验收功能覆盖开场、外景、内景、剧情、音频、移动端和部署。
系统实现内容玩家体验

2.5D 道路与导航

26 栋建筑、8 个广场、15 条道路和 3 片水域；道路吸附、路口预转向、Dijkstra 路线。
玩家能辨认校园方位，也必须在有限道路中作出选择。

外景追逐

红鬼与玩家共享路网，包含 5 秒离场安全期、最短路追击、理智伤害与贴身死亡。
追逐遵守地图结构，建筑、湖面和道路都参与策略。

第一人称内景

鼠标锁定、移动状态机、奔跑、跳跃、蹲伏、碰撞、手电、开门、拾取和小地图。
关键线索存在于真实空间位置，调查需要观察和移动。

剧情、属性与结局

5 项属性、10 类道具、剧情标记、前置条件、默认两次额外复活和 7 类终章结果。
早期选择会在后续关系、权限、证据与结局中产生反馈。

视听与移动端

环境音、程序化音效、跳脸时序、雾与暗角；虚拟摇杆、拖动视角和触控互动。
桌面端保持沉浸感，移动端也能完成主流程。

App.tsx 连接开场、外景、内景、剧情弹层、跳脸管线和死亡/复活流程。CampusScene 与 Interior3D 各自维护渲染生命周期，通过 Store 和剧情引擎交换业务状态。

FLOW 01

输入与场景切换

键鼠或触控输入进入当前活动引擎；进入建筑时暂停 Phaser、启动 Interior3D，退出后恢复外景并把玩家放回对应道路出口。

FLOW 02

剧情与共享状态

storyEngine 处理选择、属性、道具、标记和下一地点，Zustand 将结果同步给 React、Phaser 与 Three.js。

FLOW 03

模型与运行时资源

InteriorAssetLoader 读取 GLB 和场景元数据；assetUrl 根据开发或生产环境切换到本地 public 或 R2。

06 · IMPLEMENTATION

关键实现机制

技术重点集中在跨引擎协作、可维护的剧情状态、真实模型玩法化和浏览器运行效率。
机制运行路径解决的问题

双引擎生命周期

App → Phaser.pause
→ Interior3D.mount → restore

避免两个引擎同时占用输入和帧循环，室内出口还能准确映射回校园道路。

统一剧情状态

storyData → storyEngine
→ StoryState → Zustand

实体拾取、文本选择、属性变化和下一场景使用同一份状态，防止剧情与 3D 进度脱节。

路网移动与追逐

input projection → rail snap
→ mapGraph → Dijkstra

把屏幕方向投影到等距道路；玩家和红鬼共同遵守路网，路口选择和追击路径都可解释。

元数据驱动内景

main.glb + props.glb
+ scene.meta.json

模型负责视觉，元数据保存出生点、道具点、剧情点、出口、碰撞清理区和灯光锚点。

双线资源加载

assetUrl(relativePath)
→ local public / R2 CDN

开发环境支持离线资源，生产环境从 R2 读取大型资产，并通过版本参数、预加载和 Brotli 控制缓存与体积。

运行时性能控制

snapshot reuse → 10 Hz sync
→ collider skip → batching

减少帧循环中的 Zustand 写入和重复分配；静止时跳过无效碰撞扫描，静态模型批处理时保留画质。
