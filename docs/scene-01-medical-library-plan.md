# 场景一：农医馆（原著医学院图书馆）关卡策划

> 状态：规划稿 v3，不包含代码、模型导入、挖墙或 AI 生图。  
> 目标时长：首次游玩 12–18 分钟；熟练玩家 7–10 分钟。  
> 叙事范围：进入图书馆、取得照明、笔记本剧情、异常借阅小票、取得符咒、随机书架剧情、两次透明鬼影跳脸、发现坠楼者、生成出口并离开。

## 1. 先明确现有模型事实

### 1.1 手电筒

旧模型 `public/models/interiors/medical-library/scene.glb` 中存在可复用的真实手电模型：

- 节点前缀：`pickup_flashlight_visual_small_plastic_torch...`
- 网格名：`Plastic Torch`
- 旧坐标约：`(-3.166, 0.08, -2.164)`

建议把这组节点单独导出为轻量 `flashlight.glb`，之后由程序放到随机桌面锚点。不要把整份旧场景重复加载一次来取得手电。

### 1.2 整个内景的出口

旧模型中虽然有名为 `library_exit_gate_visual...` 的铁门，约在 `z=7.34`，但它不是完整的建筑出口：

- 后方 `z=9` 是一整块 `south_wall_exit_plaster` 实墙；
- 没有墙洞、门框、外部前室、玻璃门或能穿出的门扇；
- 因此它只能当作馆内档案区铁栅门，不能继续冒充整座内景出口。

当前游戏实际加载的 `public/models/interiors/library/library.glb` 没有命名的手电、主出口、剧情点或配套 metadata。它的节点大多是通用 `Geom3D`，只有后加的红色日光灯具名。运行时也因此关闭了旧的剧情点和拾取引导显示。

**结论：当前没有一个明确、可识别、可绑定、实际通向室外的主出口建模。玩家找不到是模型与点位映射问题，不是玩家路线问题。**

### 1.3 本方案的出口决策

取消“出生时就能看见主出口”和“消防门观察窗”方案。最终出口只在第四剧情完成后出现：

- 使用 `3D_Assets/门/Glass Door/Glass Door.obj`（同目录也有 FBX/MTL）；
- 位置严格对应用户最新截图中小地图底边的红色短横线，以及画面中该侧白色外墙；
- 实施时预先在 Blender 中切出与门框尺寸一致的洞，并保留一块严丝合缝的墙面遮挡件；
- 第四剧情完成前：门隐藏、完整墙面遮挡件显示；
- 第四剧情完成后：遮挡件隐藏、门显示、碰撞更新，小地图显示红色出口横线；
- 玩家碰到门后黑屏，再切换到室外场景。

## 2. 空间分区与动线

### 2.1 分区

| 分区 | 主要内容 | 叙事职责 |
|---|---|---|
| A 桌面区 | 固定笔记本桌、手电可拾取点 | P1 与基础操作 |
| B 图一小隔间 | 便签模型改作借阅小票 | 文档阅读与 P2 |
| C 图二工作桌 | 用户提供的符咒资产 | 一次性护命道具 |
| D 书架区 | 三个固定候选书位、现有红灯管 | 随机 P3 与第一次跳脸 |
| E 书架外黑暗区 | 隐蔽暗红环境光、现有路灯、现有坠楼人物 | P4、第二次跳脸、坠楼者显形 |
| F 返回书架房间 | 第四剧情后的返程路线 | 触发全部红灯管持续闪烁 |
| G 截图标红外墙 | 用户提供的玻璃门与预切墙洞 | 最终出口 |

### 2.2 完整游玩路径

```text
进入场景，取得手电
  ↓
固定桌上的笔记本成为唯一激活目标：物体猩红发光 + 小地图红点
  ↓ 触碰笔记本，关闭其红光/红点
P1 笔记本剧情与选择
  ↓
图一小隔间的小票开始猩红发光 + 小地图红点
  ↓ 触碰小票
先阅读小票全文 → 任意键继续 → P2 剧情与选择
  ↓
图二工作桌的符咒开始猩红发光 + 小地图红点
  ↓ 拾取符咒，获得一次护命
从三处固定书位中按存档种子随机选择一处
  ↓ 仅被选中的书发红光，小地图显示红点
靠近目标书 → P3 剧情与选择 → 第一次 AI 透明鬼影跳脸
  ↓
离开书架房间，进入没有明显光源的暗红黑暗区
  ↓ 此时坠楼人物隐藏、路灯关闭
接近路灯到实测触发距离 → P4 / 第二次跳脸 / “砰”声 / 选择
  ↓ J2 跳脸与“砰”声同时发生；同一时刻显示林伟并开启路灯
P4 强模糊剧情遮罩出现 → 玩家选择 → 文字与选项消散
  ↓ 遮罩解除后，玩家才清楚看见路灯下的坠楼人物
第四剧情完成
截图标红墙位出现玻璃门；小地图显示红色出口横线
  ↓
玩家返回书架房间 → 现有红灯管不断闪烁
  ↓
抵达玻璃门并触碰 → 黑屏 → 离开农医馆
```

任意时刻只能存在一个“当前目标”红光和一个对应小地图红点。前一个目标完成后先关闭，再激活下一个；读档必须恢复相同目标和相同随机书位。

## 3. 道具设计

### 已确认的用户资产

| 用途 | 源文件 | 实施前处理 |
|---|---|---|
| P1 笔记本 | `3D_Assets/笔记本（用于第一个剧情点）/binder_notebook_2k.blend` | 从 Blend 导出独立 GLB，保留原贴图 |
| P2 借阅小票 | `3D_Assets/便签（用于借阅小票）/office_notepads_2k.blend` | 选择合适便签子物体，导出 GLB，并在阅读界面显示真正文字 |
| 护命符咒 | `3D_Assets/符咒/符3+3DMAX2022/符3 3DMAX2022/符3.fbx` | FBX 已确认存在；导入 Blender 后整理材质、比例和原点，再导出独立 GLB |
| 最终出口 | `3D_Assets/门/Glass Door/Glass Door.obj` + MTL，另有 FBX | 在 Blender 中按实际尺寸整理原点、朝向、门扇与碰撞节点 |

不自行新建笔记本、小票、符咒、剧情书、路灯或人物模型。剧情点优先绑定这些用户资产或当前图书馆 GLB 的现有物体；AI 仅生成透明底跳脸图片。

### I01 手电筒（核心装备）

**外观**

- 复用旧 GLB 的黑色小型塑料手电；表面磨损，侧面贴褪色的“医学分馆”资产标签。
- 平放或斜靠在书本上，不悬浮、不旋转、不发蓝色游戏光柱。
- 在玩家两米内，红色顶灯只在手电金属边缘形成一次很弱的反光；同时播放非常轻的塑料碰桌声，提示可检查。

**随机位置**

- 每局只在出生点附近的几个可达、无遮挡桌面锚点中随机，保证手电位于玩家初始弱光能勉强扫到、步行几步可达的位置。
- 随机结果写入存档种子；读档不能重新随机。
- 手电不进入剧情引导链，不发目标红光，也不在小地图显示红点；它靠近出生点、初始弱光和外形反光被发现。
- 不再使用林伟NPC做提示；笔记本始终是第一个带红光和地图红点的剧情节点。

**能力**

- 未取得：没有画面中心光圈，只能依靠天花板红灯、应急灯和终端屏幕。
- 未取得时给玩家一个范围很短、强度很低的近身补光，只保证看见脚下、附近桌沿和手电轮廓，不能代替手电照亮房间。
- 取得后：自动点亮一次，画面中心出现真实聚光锥/柔边光圈；之后 `F` 开关。
- 场景一电量至少保证连续使用 8 分钟；不让教学关因为电量耗尽卡死。
- 有手电才能看清小字、墙后电线、泥脚印和白衣人的保护动作，但没有手电仍能走完主线。

### I00 P1 笔记本（固定剧情实体）

- 使用用户提供的 `binder_notebook_2k.blend`，不另建模型。
- 固定放在用户最新图一红圈所示桌面：小地图下方阅读区内、红圈标出的纵向桌位。实施时以该截图和 Blender 顶视图共同落点，不再随机。
- 成为当前目标时，模型材质临时增加血红/猩红 emissive，并在周围增加局部红色光晕；小地图出现对应红点。
- 玩家触碰后立即清除 emissive、光晕和地图红点，同一局不再次点亮。

### I02 异常借阅小票（固定关键证据）

**固定位置**：按图一标注，放在地图转折处的**小隔间内部办公桌面**，即带办公椅、书架和桌面设备的封闭工位。小票放在靠走道一侧，玩家进入隔间后能由手电扫到，但在隔间外不会一眼看见。

- 使用用户提供的 `office_notepads_2k.blend`，不自行创建纸片模型。
- P1 完成前不发光；P1 完成后成为唯一当前目标，模型发猩红光，小地图显示红点。
- 正面：借阅人为空、归还地点“医学院地下仓库”、时间 `23:47`。
- 背面受手电照射后浮出：“湖边不要回头。”
- 触碰后先关闭红光和地图红点，再自动进入文字道具阅读态；按任意键后继续进入 P2 剧情，而不是立刻返回游戏。

### I03 护命符纸（一次性额外生命）

**固定位置**：按图二标注，放在书架旁的**外侧工作桌桌面**，靠近文件/书本而不是电脑正中。玩家从主通道经过时能看到一小角暗黄纸面，必须走近才出现 `E 拾取符纸`。

- 使用用户提供的符咒资产，不自行建模；转换为浏览器可加载格式后放在图二工作桌。
- P2 完成前不发光；P2 完成后成为唯一当前目标，发猩红光并在地图显示红点。
- 拾取后获得 `ghostWardCharges=1`，等价于多一条针对“被鬼抓住”的命。
- 第一次鬼怪捕获或本应致死的近身攻击发生时，统一伤害管线先消耗符纸：符纸自燃、屏幕边缘闪过朱砂纹，鬼被短暂逼退，玩家不会死亡。
- 保护触发后，玩家被推回最近的安全导航点，获得约 4 秒不可再次捕获时间；符纸图标变成焦黑残片后消失。
- 它只抵挡一次鬼怪捕获，不抵挡剧情规定的林伟坠楼，也不取消普通理智损失，因此不会让恐怖机制失效。
- 后续白秋可以从焦黑残灰认出符法，保留原本的伏笔与对白价值。

拾取时关闭符咒红光和地图红点；燃烧、灰烬、逼退鬼怪仍属于程序特效，不修改源模型。

场景一不再设置备用电池。手电电量按本场景必需时长保底，不用额外补给制造无意义搜刮。

### 3.1 当前目标红光与小地图状态

`GuidanceTargetDirector` 统一保存 `activeTargetId`，不允许各剧情组件自行开灯：

```text
P1_NOTEBOOK
 → P2_RECEIPT
 → TALISMAN
 → P3_BOOK_A / P3_BOOK_B / P3_BOOK_C（三选一）
 → P4_PROXIMITY（非实体；无物体红光、无小地图红点）
 → EXIT_LINE
```

- 实体只有在成为“下一个目标”时发血红/猩红光；未解锁目标保持原始材质。
- 红光由临时 emissive override、柔和局部 PointLight 和很弱的地面红色反射组成，不增加新的可见灯具模型。
- 完成目标的同一帧关闭其红光与小地图红点，再在剧情遮罩结束后激活下一目标，避免两个红点同时出现。
- P3 三处书位随机结果写入存档种子；读档不得重新抽取。
- P4 刻意取消地图提示；玩家走出书架房间后只能依靠可见道路轮廓前进，距离触发负责突然惊吓。
- 出口不是红点。P4 完成后在小地图对应墙段绘制一条红色横线。

## 4. 四个剧情点

场景一不制作活着的林伟NPC，也不让林伟在馆内走路或表演。唯一的林伟三维实体是当前 GLB 中、用户最新图二红圈确认的坠楼人物；实施时在 Blender 中选中该现有对象组并统一命名为 `fallen_linwei`。

### P1「十点以后，有人在唱」

**实体**：`3D_Assets/笔记本（用于第一个剧情点）/binder_notebook_2k.blend`。  
**位置**：用户最新图一红圈所示的固定纵向桌位。  
**前置**：已进入场景；手电是否已拾取不作为硬锁。  
**触发**：笔记本是当前唯一红光目标；小地图同步显示红点。玩家触碰模型即关闭红光和红点，打开 P1 毛玻璃剧情。

笔记本中的文字记录林伟连续听到戏腔、闭馆时间和 `23:47`，以此承接原本由林伟NPC口述的内容。

| 选项 | 显示数值影响 | 后续 |
|---|---|---|
| 逐行检查日期和被划掉的名字 | 理智 `-2` · 线索 `+5` | `notebook_checked=true`；P2 可比对时间 |
| 用手机记下最后一页，再寻找对应票据 | 体力 `-1` · 线索 `+4` | `notebook_photographed=true` |
| 合上笔记本，先离开这张桌子 | 理智 `+2` · 线索 `+1` | 不跳过主线，但后续少一条解释 |

**完成后**：设置 `P1_completed=true`，图一小隔间的小票模型开始发红光，小地图红点移动到小票位置。

### P2「不存在的最后一条记录」

**实体**：`3D_Assets/便签（用于借阅小票）/office_notepads_2k.blend`。  
**位置**：沿用图一，小隔间办公桌面。  
**前置**：`P1_completed=true`。  
**触发顺序**：

1. 玩家触碰发红光的小票，立即关闭小票红光和地图红点。
2. 先进入 `DOCUMENT_READING`，依次显示空白借阅人、地下仓库、`23:47` 和“湖边不要回头”。
3. 全文显示后提示“按任意键继续”；任意键不直接返回游戏，而是切换到 P2 剧情文字和选项。

| 选项 | 显示数值影响 | 后续 |
|---|---|---|
| 把小票与笔记本时间逐项比对 | 理智 `-2` · 线索 `+7` | 若检查过笔记本，再获得时间线关联 |
| 用手电查看纸背和压痕 | 理智 `-3` · 线索 `+9` | **需要手电筒**；发现第二层字迹 |
| 先收进口袋，不在隔间久留 | 理智 `+2` · 线索 `+4` | 安全收益，证据仍保留 |

**完成后**：小票进入道具栏，设置 `P2_completed=true`；图二工作桌的符咒开始发红光，小地图红点移动到符咒。

### P3「没有影子的脚步」

**解锁前置**：玩家必须先拾取发红光的符咒。拾取后关闭符咒红光和红点，获得 `ghostWardCharges=1`，随后才生成书架目标。

**实体**：只使用当前 GLB 中已有的书，不新增书或其他剧情道具。实施时在书架区选择三个固定、可达、不会被其他书遮住的现有书节点，记为 `book_anchor_A/B/C`。  
**随机规则**：新游戏根据存档种子三选一；读档保持同一本。只有被选中的书发猩红光，小地图只显示该位置的红点。  
**触发**：玩家走到被选中书的实际近距离半径内自动触发，不需要精确点击书脊。

| 选项 | 显示数值影响 | 后续 |
|---|---|---|
| 抽出这本书，检查书后传来的声音 | 理智 `-4` · 体力 `-2` · 线索 `+6` | 近距离进入 J1 |
| 用手电照进书架缝隙 | 理智 `-3` · 线索 `+8` | **需要手电筒**；多看见一帧白衣人的指向 |
| 后退一步，只听声音从哪边移动 | 理智 `-2` · 体力 `-1` · 线索 `+4` | 惊吓距离稍远，但仍触发 J1 |

**第一次跳脸 J1**：剧情选择与文字完成血迹消散后，留出短暂停顿，再由统一跳脸状态机显示 AI 生成的透明底白衣鬼影图片；图片快速放大、横向抖动，叠加屏幕血滴、红闪和上下文恐怖文字。这里不加载白衣女人或绣花鞋三维模型。

**完成后**：设置 `P3_completed=true`，书架目标红光和红点消失，允许玩家走出书架房间进入黑暗区。

### P4「灯下的人」

**位置**：书架房间外的黑暗区，现有路灯与用户最新图二红圈确认的坠楼林伟附近。  
**前置**：`P3_completed=true`。  
**初态**：

- `fallen_linwei` 隐藏；
- 路灯关闭；
- 黑暗区使用没有可见灯具来源的低强度暗红环境光，使玩家看得清道路轮廓但看不见人物；
- 玩家接近路灯到一段实测距离时才触发 P4，距离在实施时根据当前模型比例测定。

**锁定演出时间轴**

1. 玩家走出书架房间；此时 `fallen_linwei` 隐藏、路灯关闭，地图不显示 P4 红点。
2. 玩家距离路灯仍有一段距离时进入隐藏触发半径。
3. 同一时刻执行四件事：J2 透明鬼影突脸、前端合成“砰”声、显示 `fallen_linwei`、开启路灯猩红聚光。
4. J2 短暂退场后立刻打开 P4 剧情毛玻璃和正文。P4 使用比普通剧情更强的背景模糊，让玩家只能隐约看见灯和地面人形，不能在选择前看清林伟。
5. 玩家作出选择；被选项出现血迹，正文与选项按统一规则消散。
6. 毛玻璃完全解除后，玩家恢复控制，第一次清楚看见红灯下坠楼的林伟。

**第二次跳脸 J2**：使用与 J1 不同的 AI 透明底鬼影图和独立文字池，仍由统一状态机控制突然放大、震动、红闪和屏幕血滴。  
**坠楼声**：用前端 Web Audio 合成“砰”声，不依赖外部录音；由低频冲击、短噪声和极短金属尾音组成，并做峰值限制。

| 选项 | 显示数值影响 | 后续 |
|---|---|---|
| 立刻靠近确认那个人是否还有反应 | 理智 `-7` · 体力 `-6` · 线索 `+5` | `approached_fallen_person=true` |
| 先拨 120 和保卫处，报清当前位置 | 理智 `-4` · 体力 `-2` · 线索 `+6` | `called_help_early=true` |
| 留在光线边缘，用手电观察周围 | 理智 `-5` · 体力 `-1` · 线索 `+8` | **需要手电筒**；取得额外现场信息 |

**揭示结果**：

- `fallen_linwei` 已在 J2 与“砰”声发生时显示；选择阶段由强毛玻璃遮蔽细节；
- 打开现有路灯，使猩红色窄光束直射人物，不照亮整个区域；
- 设置 `library_final_beat_done=true`；
- 截图标红墙位显示玻璃门并开放碰撞通道；
- 小地图在同一墙位显示红色出口横线；
- 玩家重新进入书架房间时，全部现有红灯管开始不规则持续闪烁。

## 5. 出口状态机

```text
SEALED_WALL
  ├─ 第四剧情前：墙面遮挡件显示
  ├─ 玻璃门隐藏、门洞碰撞保持封闭
  └─ 小地图不显示出口

P4_COMPLETED
  ├─ 隐藏墙面遮挡件
  ├─ 显示用户提供的玻璃门
  ├─ 更新墙洞/门碰撞
  └─ 小地图在截图标红墙段画红色横线

EXIT_AVAILABLE
  ├─ 玩家返回书架房间，红灯管持续闪烁
  └─ 玩家触碰门模型或门槛触发体

EXITED
  └─ 立即黑屏 → 自动保存 → 切换室外场景
```

出口不能只是一块空气触发区，但也不再额外设计闸机、绿色安全灯或前室模型。可见出口实体只使用用户提供的玻璃门；其余只处理墙洞、遮挡件和碰撞。

### 5.1 主出口的建模和放置方案

不自行设计或生成门模型。导入 `3D_Assets/门/Glass Door/Glass Door.obj`，位置严格使用最新截图小地图底边红色短横线所标墙段。

单靠前端运行时布尔运算挖穿大型 GLB 风险过高，因此在 Blender 资产准备阶段完成：

1. 导入图书馆和 Glass Door OBJ；
2. 按门框实际宽高在标红白墙上切出同尺寸洞；
3. 保留一块与原墙材质一致的可切换遮挡件 `exit_wall_cover`；
4. 整理 `exit_door / exit_trigger / exit_wall_cover` 三组独立节点；
5. 导出到游戏资产后，第四剧情前显示遮挡件，完成后切换成门。

玩家视觉上会看到“第四剧情之后墙上突然出现出口”，但实现不会在运行时临时破坏网格。

### 5.2 出口中哪些由程序完成

- P4 前后节点显隐、墙洞碰撞切换、小地图红线和黑屏切场景由关卡状态机完成。
- 玩家触碰门即可触发黑屏，不要求播放开门动画或真正穿过门槛。
- 门的 OBJ/MTL/FBX 都保留在源资产目录；实施时选最稳定的格式导入 Blender并导出 GLB。

## 6. 红光引导与环境灯光

### 6.1 实体目标红光

- 笔记本、小票、符咒以及 P3 随机选中的现有书，在其成为“下一个目标”时整件物体出现血红/猩红色光晕。
- 光晕允许明显到足以引导玩家，但物体不悬浮、不旋转；完成触碰后立即熄灭且不再复亮。
- 小地图用同一 `activeTargetId` 数据绘制红点，不能由另一套坐标手写，避免世界位置与地图位置不一致。
- 未被抽中的另外两本候选书保持普通材质，不出现任何提示。

### 6.2 书架外黑暗区

- 不增加可见光源模型。
- 使用隐藏的低强度红色区域光、很弱的红雾和地面间接色，让通路轮廓可见，但远处坠楼人物不可见。
- P4 前现有路灯保持关闭，人物组保持 `visible=false`。
- P4 揭示时只打开路灯的猩红色聚光锥，光束笔直打向坠楼人物；周围区域仍保持黑暗。

### 6.3 场景基础可见度

- 当前天花板红灯管整体偏暗，实施时提高其常亮状态的 emissive 与实际红色灯光强度。
- 调亮目标是：没有手电时仍能辨认近处桌椅边缘和基本通路，但不能看清远处小字、书架缝隙或黑暗区人物。
- 玩家未取得手电前增加极弱、短距离的随身补光；取得手电后立即关闭该补光，避免和真实手电光圈叠加。
- 红灯管增亮后仍保留深阴影，不把画面变成均匀红色；实施时以“看得见路、看不清危险”为验收标准。

### 6.4 返回书架房间

第四剧情完成并揭示人物后，第一次从外部重新跨入书架房间边界时触发 `library_return_flicker=true`。现有红灯管进入不规则循环：每组亮灭周期不同，偶尔连续闪两次，不使用所有灯完全同步的机械闪烁。

## 7. 统一跳脸状态机

所有场景的跳脸都交给同一个 `JumpscareDirector` 管理，剧情只发请求，不直接各写一套动画和音效。

### 状态

```text
IDLE
 → TELEGRAPH      预兆：灯闪、歌声、短静音
 → IMPACT         透明鬼影 PNG 突现放大、震屏、血滴、理智结算
 → AFTERIMAGE     残影、耳鸣、文字闪现
 → RECOVER        逐步恢复控制和曝光
 → COOLDOWN       硬惊吓保护期，禁止连续轰炸
 → IDLE
```

### 上下文请求参数

- `context`：`library_book_ghost`、`library_fall_ghost`、`ghost_close`、`ghost_caught` 等。
- `intensity`：soft / medium / hard。
- `sanityDamage`：统一结算，护身符与保护期也在这里处理。
- `imageAssetId`：J1/J2 使用不同的透明 PNG。
- `audioSet`：戏曲破音、呼吸、低频冲击的组合；P4 的“砰”由单独 Web Audio 事件控制。
- `cameraRule`：允许震动，但不能强转玩家视角 180°。
- `textPool`：按上下文随机，最近 5 条不得重复。
- `bloodDripProfile`：屏幕上沿血滴数量、速度、长度和透明度。

### 场景一 J1：书架鬼影文字池

- “她在书架后面”
- “别抬头”
- “你身后还有一双脚”
- “23:47”
- “她看见你了”
- “那不是歌声”

### 场景一 J2：灯下坠楼文字池

- “灯下有人”
- “刚才那里是空的”
- “别走过去”
- “她站在他后面”
- “你听见落地声了吗”
- “他一直在等灯亮”

文字只闪现 250–500ms，不覆盖关键选择。硬惊吓后至少 45 秒不再触发另一场硬惊吓；可选环境软惊吓最多再出现一次。

### 7.1 跳脸到底靠什么实现

场景一不制作或加载任何白衣女人、鬼影、绣花鞋三维模型。正式强惊吓使用 AI 生成的透明底恐怖 PNG，并沿用旧版“瞬间突脸”的核心节奏：

1. **素材生成**：实施阶段根据小说设定分别生成 J1 和 J2 两张透明底鬼影图；人物形象一致，但姿态、构图和表情不同。现在只记需求，不开始生图。
2. **预兆**：环境音短暂归零 0.15–0.25 秒；J1 可配合书架红灯骤暗，J2 配合黑暗区曝光下降。
3. **突现**：透明图从屏幕中心约 `scale(0.22)` 在 120–180ms 内放大到 `scale(1.45–1.8)`，叠加小角度左右抖动和随机 1–2° 旋转。
4. **血滴层**：屏幕上沿出现不规则血色滴流，先形成厚重血线，再有数条不同速度的滴痕向下；它是 Canvas/CSS/SVG 后期，不是模型。
5. **冲击层**：短白闪转暗红、色差、暗角、受控震屏、上下文文字与统一音效同时触发。
6. **退场**：鬼影在 0.5–0.8 秒内扩大并透明消失；血滴稍晚淡出，随后恢复视野并进入冷却。

AI 图必须输出真正透明背景 PNG，不带矩形黑底、场景背景、文字或血框。J1 形象偏“书架间突然逼近的湿发白衣鬼影”；J2 偏“从黑暗中贴近、指向灯下人物的同一鬼影”，不直接画坠楼尸体。

`JumpscareDirector` 只负责表现和结算请求；鬼怪真正抓住玩家时再走 `GhostDamage` 管线。该管线会先检查 `ghostWardCharges`，有符纸则消耗一次保护、播放符纸自燃和逼退动画，没有才进入死亡/读档流程。这样所有场景都能复用同一套规则。

## 8. 新剧情遮罩与选项交互

后续所有剧情弹框统一替换，不再使用圆角矩形卡片。

### 8.1 入场

1. 暂停玩家移动、碰撞伤害和鬼状态推进。
2. 游戏背景保留可见，但覆盖全屏毛玻璃：`blur 12–16px`、降低饱和度和亮度，叠一层黑红薄雾与细颗粒。
3. 环境音降低约 8–12dB，但保留方向感；剧情翻页声和人物声音保持前景。
4. 正文像游戏前言一样逐行显现，每行 0.25–0.45 秒；玩家可点击立即显示全文。

正文直接排在遮罩上，不放入封闭卡片。可以用一条极细竖线、页码或时间戳建立层级，但不画圆角外框。

### 8.2 选项

- 位于屏幕下部；每项为一整行。
- 左侧：选择文本。
- 右侧：严谨列出直接数值影响，例如 `理智 -2　线索 +3　信任 +6`。
- 需要道具的选项在右侧写 `需要：手电筒`；未满足时保留可见但不可选择。
- 没有直接数值变化时写 `无直接变化`，不能留空让玩家猜。
- 关键分支旁可出现很小的“绳结”符号，表示会影响后续，但不提前剧透具体结果。
- 数值预览与实际结算必须读取同一份 choice 数据，杜绝 UI 写 `-2`、实际扣 `-5`。

### 8.3 选择后的血迹与消散

1. 玩家点击后立即锁定输入，防止重复选择。
2. 被选中的整行从文字下方渗出暗红血迹，像纸面吸收液体，不是喷溅贴图盖住文字。
3. 未选选项先降低透明度；被选项停留约 450ms，让玩家确认结果。
4. 血迹向两侧拉长，正文从最后一行开始像灰烬一样逐行消散。
5. 毛玻璃在 700–1000ms 内解除，背景重新对焦，玩家恢复控制。
6. 若选择触发真实空间中的惊吓，至少留 0.8–1.5 秒可移动缓冲，不在遮罩刚消失的同一帧跳脸。

提供“减少动态效果”设置：关闭血迹扩散和大幅震屏，改为短暂暗红下划线与淡出。

### 8.4 有文字道具的阅读遮罩

借阅小票、纸条、病历、日记等带文字道具统一复用剧情毛玻璃系统，但进入独立 `DOCUMENT_READING` 状态，不显示选项和数值栏。

1. 玩家对图一桌面的小票按 `E`，先用 0.3 秒把视线轻引向纸面，再覆盖全屏毛玻璃并暂停移动、鬼怪推进和伤害。
2. 小票不是放进圆角卡片，而是以略微倾斜的热敏纸轮廓悬在暗背景中央；标题、借阅字段、`23:47` 和背面字迹逐行显现。
3. 读到最后一行时，远处戏腔和纸张摩擦声才进入前景。若玩家有手电，背面“湖边不要回头”更清晰；没有手电也能读完必要信息。
4. 首次拾取时，全文出现后监听任意键；按键后纸张从边缘焦黑并像灰屑一样消散，但不恢复移动，而是无缝切换到 P2 剧情文字与选项。
5. P2 选择完成、文字血迹消散后，才设置 `receipt_taken=true`、把小票加入左侧道具栏并恢复游戏，同时激活符咒红光和地图红点。
6. 从道具栏重复查看时，任意键只关闭文档，不重复触发 P2 或结算线索。

这一系统主要是 UI、状态机、音效和粒子效果；三维世界使用用户提供的便签模型。

## 9. 关卡常驻界面规划

### 9.1 左上角场景名

- UI 与地图沿用**“农医馆”**，文档可注明其对应原著开场的医学院图书馆/医学分馆；不要与后续“医学院教学楼”混同。
- 桌面端建议字号 34–40px，比当前标题放大约 25%–35%，仍保留克制的旧金/象牙色和轻微颗粒。
- 标题只负责地点识别，不再与道具数量或任务提示挤在同一行。

### 9.2 左侧道具栏

- 按图三标注放在屏幕左侧，位于场景名下方，纵向排列；桌面端宽约 240–280px。
- 每个格子显示小图标、名称和一次核心用途：手电筒显示开/关；小票显示“已阅读”；符纸显示朱砂符号和 `×1`。
- 空槽使用低对比灰线，不使用明亮手游式边框。靠近可交互道具时，对应空槽只轻微呼吸一次，不持续闪烁。
- 符纸触发后，该格先出现焦黑裂纹，再在 1 秒内变成灰色“已消耗”，让玩家明确多的一条命已用掉。
- 左侧栏只放道具，不混入理智、体力或剧情任务，避免信息职责重叠。

### 9.3 右侧剧情链条

- 小地图保留在右上角；按图三标注，剧情链纵向放在小地图下方，替代当前孤立的“寻找出口”大按钮。
- 场景一链条为：`笔记本里的歌声 → 23:47 → 没有影子的脚步 → 灯下的人 → 离开图书馆`。
- 已完成节点使用低亮旧金色和细实线连接；当前节点用象牙白文字、暗红血痕和缓慢呼吸高亮；未游玩节点统一灰色，只显示“未解锁”或模糊标题，避免提前剧透。
- 完成 P4 后，最后节点“离开图书馆”由灰色变成血红色，并与小地图出口红色横线同步。
- 节点只展示剧情进度，不直接点击传送，也不显示未达成节点的完整内容。

窄屏时左右栏可各折叠为图标抽屉，但标题、当前剧情节点、手电和符纸剩余次数必须始终可见。

## 10. 实现分层：哪些需要建模，哪些不需要

| 内容 | 是否需要新模型 | 主要实现方式 |
|---|---|---|
| P1 笔记本 | 不新建 | 导入用户 Blend，固定桌面，红光/地图点/触碰由状态机控制 |
| P2 小票 | 不新建 | 导入用户便签 Blend，放图一桌面；首次阅读后直接进入 P2 |
| 符咒 | 不新建 | 导入用户新提供的 `符3.fbx`，整理后导出 GLB，放图二桌面；状态机提供一次护命 |
| P3 三本候选书 | 不新建 | 绑定当前 GLB 三本现有书，新游戏三选一发红光 |
| P4 路灯与坠楼人物 | 不新建 | 复用现有路灯和图二圈出的林伟对象；J2时同步显形与开灯 |
| 手电筒 | 需要，但可复用旧模型 | 从旧 GLB 单独导出，只在出生点附近锚点随机；不显示红光/地图点 |
| 主出口 | 不新建门，需修改墙体 | 导入用户 Glass Door OBJ；Blender 预切洞和遮挡件；P4 后切换显隐 |
| 两次跳脸鬼影 | 不使用3D模型 | 实施时 AI 生成两张透明 PNG；放大、震动、血滴、文字、红闪和冷却由统一导演完成 |
| 左右 HUD、剧情/文档遮罩 | 不需要 3D 模型 | React/CSS/后期模糊、状态机和数据驱动渲染 |

本场景不再自行创建剧情实体或鬼影模型。三维实体来自用户资产和当前 GLB；前置关系、红光目标、地图点、随机书位、人物显隐、路灯、剧情链、毛玻璃、血滴跳脸、护命与出口切换全部由数据和状态机实现。所有点位通过独立 metadata 记录 `id / position / radius / prerequisites / visualAnchor`，不把关卡逻辑烘死在 GLB 节点名称里。

## 11. 难度与数值验算

场景一从 `理智 100 / 体力 100 / 线索 0 / 信任 50` 开始。

- 常规认真调查路线结束约：理智 80–88、体力 85–94、线索 18–28、信任 50。
- 最保守路线结束约：理智 89–95、体力 92–97、线索 9–15、信任 50。
- 高风险搜证路线结束约：理智 78–86、体力 88–94、线索 26–35、信任 50。

场景一没有活着的林伟或其他可建立关系的角色，因此暂不改变信任值；该数值保留给后续场景。

第一场不应把理智压到 60 以下，也不能因没找到手电而死亡。手电提供信息优势、视觉安全与额外选项，而不是主线硬钥匙。
