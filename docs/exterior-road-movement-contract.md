# 外景道路移动契约

本文定义校园外景中键盘与触摸摇杆的道路移动语义。实现、地图数据和回归测试均须遵守本契约；不得为单个岔路添加坐标特判。

## 1. 坐标与意图

- 玩家输入表示屏幕上看到的方向。`W/A/S/D`、方向键和触摸摇杆先归一化为屏幕方向，再参与分支判断。
- 道路拓扑、碰撞、寻路和玩家位置使用地图逻辑坐标。屏幕方向与逻辑方向之间只能通过当前等距投影参数转换。
- 分支匹配以候选道路渲染到屏幕后的方向与玩家屏幕输入的夹角为准。不得直接拿屏幕输入与地图逻辑方向比较。

## 2. 候选道路

- 不在决策点预判范围内时，候选项只能是承载玩家的当前道路边的前进和后退方向。
- 进入预判范围后，候选项只能来自当前道路边端点所连接的真实道路边。邻近但不与该节点相连的道路不得成为候选项。
- 地图中的相连道路必须共享同一个逻辑节点坐标；禁止依赖道路数组顺序、最近道路遍历顺序或视觉上的“看起来相交”。

## 3. 预选、过节点与转向

- 玩家可以在到达节点前预选分支。
- 预选分支不能让玩家从当前道路横向切向尚未到达的分支，也不能产生零位移。
- 每一帧的移动预算必须先沿当前道路走到节点，再把剩余距离用于已选的出边；不得凭空增加或丢失距离。
- 如果玩家选择当前所在的出边，则语义为掉头，应直接沿该边远离节点。
- 经过节点后，玩家必须落在选中的道路边上；道路吸附只能修正浮点漂移，不能重新选择分支或把玩家传送到其他边。

## 4. 分支选择与方向锁

- 明确的玩家输入优先于上一帧方向。玩家按向右下时，可见的右下分支必须能够覆盖之前的右上方向锁。
- 红色虚线路由经过当前决策节点时，若玩家输入与虚线的下一条出边相容且没有明确指向其他分支，应优先选择虚线方向。
- “相容”统一定义为归一化屏幕方向点积不低于 `0.5`，并且它与角度最佳候选的分数差不超过 `0.15`；不得按地图坐标或路名另加特判。
- 虚线优先级是输入消歧，不是自动寻路：反向输入或明确指向其他分支时，必须尊重玩家输入。
- 方向锁只用于输入无法区分候选项的真实角度并列。例如两个分支相对纯右输入完全对称时，保持当前分支可避免无意抖动；玩家加入上/下分量后必须立即改选。
- 键盘的八个方向必须能够选中每个已配置岔路的每一条出边，且不受先前方向锁影响。
- 键盘和触摸摇杆共用同一选择函数；不得维护两套岔路规则。

## 5. 必须保持的性质

- **可达性：** 每个三岔或多岔节点的每条出边都可通过合乎其屏幕朝向的输入进入。
- **前进性：** 有合法输入且存在合法候选边时，不得因“先斜切、再吸附”而原地踏步。
- **连续性：** 一步内的轨迹只能是“当前边 → 共享节点 → 选中出边”。
- **引导一致性：** 移动判定使用的引导路线必须与当前帧绘制红色虚线的路线相同；不得另算一条隐藏路线。
- **确定性：** 同一位置、输入、引导路线和方向锁必须得到同一结果，不依赖道路或候选数组顺序。
- **等价输入：** 键盘、方向键和触摸摇杆表达相同屏幕方向时，结果必须相同。

## 6. 验收

运行 `npm run test:road-movement`。测试至少覆盖：

1. 戏院附近真实岔路 `(10.2, 11.6)`：从节点前按右下，先到节点再进入屏幕右下分支，过程中不得原地踏步。
2. 没有引导路线时，纯右输入无法区分上下对称分支则保持原方向；红色虚线指向其中一支时，纯右输入优先沿虚线，明确的反向/另一分支输入仍覆盖引导。
3. 全地图所有三岔及多岔节点的每条出边，都能由屏幕对齐输入和至少一个键盘方向明确选中。
4. 选中分支前后不偏离道路，移动预算在跨节点时保持连续。

## 7. 外景目标的安全触发

- 所有当前剧情热点模式（`indoor-3d`、`outdoor-text`、`outdoor-to-indoor`）都必须保留热点半径内的 `E` 键手动触发。
- 所有模式同时共享 `1.05` 地图单位的近距离自动触发；进入该范围后不要求玩家停下按键。
- 接近检测和自动触发必须先于同帧鬼碰撞判定。有效互动开始后应立即隐藏并暂停鬼，待剧情或室内状态解锁后再按正常延迟重生。
