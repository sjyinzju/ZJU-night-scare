## 二、项目简介

### 2.1 项目背景

“浙大夜惊魂”是一款基于校园传说进行再创作的网页恐怖游戏。玩家扮演生命科学系学生张超，在深夜陪同室友林伟进入农医馆后，遇到停滞在 23:47 的异常借阅记录。随着林伟坠楼、白秋的警告、旧档案中的姓名和被剪改的唱段逐步浮现，玩家需要穿过校园与多个建筑内景，判断哪些记录可信、哪些选择值得冒险，并阻止小剧场中的最终仪式。

项目并非单纯的文字阅读器或地图 Demo，而是将以下体验整合为一条可游玩的流程：

- 校园层面的 2.5D 等距探索与道路导航；
- 建筑层面的第一人称 3D 场景与实体互动；
- 由属性、道具、标记位和人物关系共同驱动的分支叙事；
- 追逐、跳脸、闪电、灯光、音频和低理智特效组成的恐怖表现；
- 桌面端与移动端统一支持；
- GitHub Pages 与 Cloudflare R2 分离部署的在线版本。

### 2.2 项目要解决的问题

游戏从软件团队黑客松之前的游戏沙拉起步，提出要把校园经典的恐怖小说做成第一人称剧情游戏的想法。

传统校园传说常以长文本或短视频形式传播，氛围主要依赖阅读和想象，参与感有限。本项目尝试解决的问题是：

> 如何将熟悉的校园空间、地方性传说和网页技术结合，让玩家通过“移动、观察、互动、选择和逃生”亲自推进故事，而不是只被动阅读剧情。

为实现这一目标，团队没有停留在单一展示页面，而是逐步完成了文字原型、2.5D 校园地图、第一人称 3D 内景、定制模型、剧情状态机和完整终章。

### 2.3 目标用户与使用场景

- 喜欢校园怪谈、恐怖叙事和探索游戏的玩家；
- 希望在浏览器中直接体验、无需安装客户端的轻量用户；
- 黑客松、软件团队成果展示、路演与校园文化创意展示场景；
- 用于展示 Web 游戏多引擎协作、3D 资产接入与 AI 辅助开发的技术案例。

### 2.4 项目特色

1. **真实校园空间再创作**：以紫金港校区建筑、道路、湖区和宿舍区为基础重构可探索地图。
2. **2.5D 与 3D 无缝切换**：外景使用 Phaser，内景使用 Three.js，由 React 和 Zustand 统一编排。
3. **叙事与空间绑定**：剧情点、道具、出口和惊吓都落实到 3D 坐标与元数据，而不是仅在界面中播放文本。
4. **选择真正影响结局**：最终结果综合证据、理智、体力、线索、信任、好感、道具和最终行动。
5. **完整的恐怖表现管线**：将图片跳脸、程序化视觉、屏幕震动、低频音效和场景灯光进行统一时序控制。
6. **工程化资产发布**：网页代码由 GitHub Pages 发布，大型模型与音频由 Cloudflare R2 承载。

## 五、项目架构与实现

### 5.1 总体架构

~~~mermaid
flowchart TD
    User[桌面端 / 移动端玩家] --> React[React 游戏壳层]
    React --> Launch[开场、剧情、HUD、背包、结局]
    React --> Phaser[Phaser 2.5D 校园外景]
    React --> Overlay[InteriorOverlay]
    Overlay --> Three[Three.js 第一人称内景]

    Story[storyData + storyEngine] --> React
    Map[mapData + mapGraph + roadMovement] --> Phaser
    Store[Zustand 全局状态] <--> React
    Store <--> Phaser
    Store <--> Three

    Meta[场景元数据 JSON] --> Loader[InteriorAssetLoader]
    Assets[GLB / 图片 / 音频] --> Loader
    Loader --> Three

    AssetURL[assetUrl] --> Public[本地 public]
    AssetURL --> R2[Cloudflare R2]
    Pages[GitHub Pages] --> React
~~~

### 5.4 关键工程设计

#### 双引擎协作

外景进入建筑时，Phaser 暂停，Three.js 接管输入和渲染；退出时恢复 Phaser，并把玩家放回对应道路出口。React 持有总编排权，Zustand 保持状态一致。

#### 剧情状态统一

剧情、实体道具、属性变化和出口路由均写回同一 StoryState，避免出现“3D 中已拿到物品，但文字剧情不知道”的双重状态。

#### 模型与玩法解耦

精细模型负责视觉表现，meta.json 负责出生点、道具点、剧情点、出口、碰撞清理区和灯光锚点。更新模型时可同步元数据，不需要把所有坐标硬编码到 React。

#### 资源双线加载

- 本地开发：assetUrl() 从 public/ 加载；
- 生产环境：同一相对路径指向 Cloudflare R2；
- 网页代码、主页和展示页由 GitHub Pages 发布；
- 大型 GLB、音频和剧情图片不进入 Git 仓库；
- 资源使用版本参数和 Brotli 发布，降低缓存与加载问题。

### 7.2 完整操作流程

1. 打开在线游戏或本地开发地址；
2. 阅读开场文字，等待农医馆资产读取完成；
3. 点击进入第一人称场景，跟随小地图红点寻找手电筒；
4. 依次调查笔记本、借阅小票、符咒、异常书架和灯下人物；
5. 离开农医馆进入 2.5D 校园，沿红色虚线前往下一地点；
6. 避开红鬼，利用建筑离场后的 5 秒安全期拉开距离；
7. 进入白沙宿舍，完成相框、阳台和论坛事件，并逃离走廊；
8. 在临湖餐厅、杜学民办公室等地点通过选择获得门禁、日记和人物信任；
9. 进入医学院，依次完成六层、车库和地下仓库调查；
10. 前往东教学区和启真湖拼合证据；
11. 进入小剧场，调查胶片和后台，完成追逐与最终放映；
12. 根据已有证据、属性、关系和最终选择进入对应结局。

git clone https://github.com/sjyinzju/ZJU-night-scare.git
cd ZJU-night-scare
npm install
npm run dev

本地完整运行需要额外恢复被 Git 忽略的 GLB、图片与音频资源。生产环境通过 VITE_ASSET_CDN_URL 从 Cloudflare R2 读取这些资源。

## 九、风险、限制与后续计划

### 9.1 当前限制

1. 大型 GLB、音频和部分图片不随 Git 仓库分发，本地完整运行依赖独立资产包；
2. 生产环境同时依赖 GitHub Pages 和 Cloudflare R2，发布时必须保证代码与资产版本同步；
3. 主 JavaScript 分块体积较大，Vite 构建存在 chunk size 警告；
4. 不同移动设备的 GPU、内存和浏览器策略差异较大，仍需扩大真机覆盖；
5. 项目当前未提供独立 LICENSE，代码和美术资源的再使用边界需要后续明确；

### 9.2 后续优化方向

- 对 Phaser、Three.js 和各内景玩法进行更细粒度的动态加载；
- 增加设置页，提供音量、闪烁减弱、镜头晃动和性能档位；
- 扩大移动端真机与浏览器兼容性测试；
- 为农医馆、白沙和医学院补充更多模型级回归测试；
- 建立带版本号的资产清单，自动化 Pages 与 R2 联合发布；
- 增加存档、章节选择和结局图鉴；
- 补充正式许可证、素材来源和署名信息。
