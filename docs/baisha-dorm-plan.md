## 0. 2026-08-24 锁定的寝室段方案（实施时以本节为准）

本节是用户最新确认并已实现的寝室流程，优先级高于本文后面的早期候选方案。

### 0.1 空间朝向与出生

- 小地图只对纵向进行翻转，保持左右关系不变，使四床寝室从右上方移动到右下方。
- 最终编号固定为：面对门时，靠门一排从左到右是 `1、2`，靠阳台一排从左到右是 `3、4`。
- 出生位置：3 号位，玩家面对寝室门时的左侧、靠阳台的椅子旁。
- 出生朝向：正对寝室门。出生胶囊必须落在椅子与桌沿碰撞体之外，不能靠无碰撞模式通过。
- 第一剧情点：2 号位书桌，放置用户提供并已去除埃菲尔铁塔贴图的相框。
- 第三剧情点：1 号位电脑。
- 寝室灯、阳台灯和走廊灯不闪烁；当前被点亮的灯管保持稳定。窗外局部闪电间隔为随机 7–9 秒。

### 0.2 D-PHOTO：相框与双照片演出

相框不是可拾取道具，不进入背包，也不是医学院后续获得的苏婉老照片。它是林伟留下的一张普通校园合照在白沙异常力量下发生的短暂变化。

触发前：

1. 相框位置在小地图上显示红点。
2. 玩家进入交互距离后自动触发并锁定移动/视角，隐藏地图红点；相框不要求按 `E`。
3. 先使用现有毛玻璃剧情文字表现：照片大致是一群同学在启真湖或教学楼前的合照，光线偏暗，每个人都在笑；玩家被提示仔细观察，并意识到背景似乎有不协调之处。
4. 文字与相框图片必须在遮罩期间完成预加载。加载完成后，底部显示“点击任意位置查看”。

第一张照片：

- 点击后由黑场渐入，显示相对正常的校园合照。
- 人物是 2008 年前后的中国大学生，林伟的位置固定，后续异变照必须保持完全相同构图。
- 所有人的笑容略显僵硬、不自然；背景中藏有第一次查看未必立刻发现的异常，例如远处湿漉鬼影、倒影错误或一只绣花鞋。
- 无 UI 按钮，照片固定显示 4 秒。

照片异变：

1. 第 4 秒，窗外播放一次显著强于常规闪电的雷声。
2. 雷声峰值同步播放全屏白闪，紧接一次很短的全屏红闪；照片本身不能在闪光前提前切换。
3. 闪光遮蔽期间将第一张照片原位替换为同构图异变照：林伟从照片中被抹去；其他同学五官消失但头发、衣着和姿势不变；林伟原位置出现鬼影；原场景几何不变，只变成暗红、受潮、压抑的异常版本。
4. 第二张照片固定显示 3 秒，期间不允许跳过，避免玩家错过异变。
5. 3 秒后底部显示“按任意键或点击任意位置继续”。操作后照片按现有剧情文字的颗粒/消散方式退场，恢复寝室控制。

该事件只设置一次性剧情标记，例如 `baishaPhotoSeen=true`；不写入 inventory。

### 0.3 D-BALCONY：三次敲窗与闪电剪影

照片消散并恢复寝室后：

1. 从阳台玻璃方向播放三次敲击，节奏建议为 `敲—0.55s—敲—0.9s—敲`，音量和低频逐次增加。音效允许使用 Web Audio 程序化合成。
2. 此时才在小地图阳台位置生成红点，不提前泄露阳台事件。
3. 玩家进入阳台触发区后锁定移动，播放一次比日常更大的雷声与全屏白闪。
4. 白闪期间在闪电白光层中叠加一张低透明度纯黑人形遮光蒙版：它是远处贴在光源/玻璃前挡住白光的阴影，不是向镜头缩放或直接突脸。剪影只出现一个闪光周期，不制作具体五官或三维人物。
5. 白闪结束后等待 2 秒，再进入与场景一一致的标准剧情点：无卡片边框，包含章节、地点、标题、逐段剧情文字和选项；选项必须实际结算属性并写入调查记录。

阳台剧情建议正文：

> 第三下敲击停在玻璃正中，与你肩膀几乎同高。这里没有树枝，也没有任何人能站在窗外。闪电落下的一瞬，惨白电光把栏杆和窗框压成一张平面，一团狭长暗影随之钉在玻璃中央。肩颈与湿透长发的轮廓被雨水揉得发虚，冷光从它肋下与手臂之间漏过。白光熄灭后，栏杆上什么也没有，玻璃外侧只剩三道缓慢向下滑落的水痕，寝室倒影里却短暂多出第五个人影。
>
> 贴身符纸骤然发热，走廊深处传来与医学院相同的半句戏腔。寝室里的老式显示器随即自行通电，靠门左侧的电脑亮起猩红屏幕。三道水痕继续下滑，最后在玻璃上连成模糊的“23:47”——与借阅小票上的异常记录一致。如果林伟在出事前也看见过这一幕，他留下的答案或许就在那台电脑里；但这也可能是白沙主动递出的第一条假路。

剧情框消散后移除阳台红点，激活电脑红点和电脑屏幕红色发光。

### 0.4 D-FORUM：伪校园论坛

- 目标位于 1 号位，即面对寝室门时左侧、靠门床位的电脑。
- 激活后电脑屏幕发稳定暗红光，小地图显示红点。
- 交互后沿用现有剧情转场的遮罩与消散时序，但内容层不显示章节标题、剧情标题或选项框。
- 屏幕搭建一个占据完整画面的 2008 年校园 BBS/论坛页面，从屏幕顶部向下逐步展开；只能浏览指定的一篇缓存帖子，不可访问导航、其他帖子或外链。
- 必须实际滚动到帖子底部才开始 1 秒计时；如果玩家中途滚回上方，计时暂停或重置。这个等待判定完全隐藏，不显示“停留 1 秒”“读取完成”等程序性提示。
- 倒计时完成后显示“按任意键或点击任意位置退出”。操作后论坛页面按剧情文字的消散效果退场。
- 用户继续后，9 楼原回复在原帖位置瞬间变成放大、发红并闪烁的“快逃！”，短暂停留后论坛才消散并移除寝室门。

帖子内容方向：

- 标题应像真实学生发帖，例如《白沙 216 半夜有人敲窗，真不是恶作剧》。
- 开头是普通宿舍抱怨：23:47 三次敲窗、楼层外没有树、室友以为是水管声。
- 回复前半保持真实校园论坛语气，有调侃、质疑、宿管和线路老化等解释。
- 中段逐渐出现旧住户证言：相同寝室、相同时间、照片里人数与现实人数不一致、玻璃外侧出现水痕。
- 后段把医学分馆歌声、医学院封条、启真湖倒影和小剧场亮灯连接起来，但不能直接揭露“苏婉是凶手”；应保留她可能是在警告学生的反转空间。
- 最后一条缓存回复显示为林伟账号或疑似林伟账号，时间为当晚 `23:47`，内容类似：“门外那段走廊不是出口。她让我别回答名字。”
- 正文已按用户确认的策划口径实现；使用 2006 年发帖与 2008 年离线缓存外观，不使用占位 lorem 或现代社交媒体语言。

### 0.5 D-DOOR：门消失与离开寝室

论坛消散后恢复寝室。不是播放开门动画，而是让寝室门从视觉上完全消失，同时原子移除对应碰撞体，玩家可以进入走廊。

门消失的约束：

- 论坛关闭前，门始终存在且保持真实碰撞。
- 视觉门和碰撞必须同一帧切换，不能留下空气墙，也不能先穿门后消失。
- 门框和周围墙体保留，只消失门扇；门后的走廊必须已完成加载。
- 已通过 Blender/GLB 检查确认门板节点 `组“870”#1`、`Group#794` 以及两侧完整门把手父组件 `Group#785`、`Group#785_1`，并在元数据中统一绑定。论坛结束后门板、门把手和独立门碰撞在同一流程中移除；静态墙体碰撞按门洞清理区切割，门框与两侧墙体保留且不再留下空气墙。
- 第一处右转后、挂有安全出口标识的合法纵向通道中心线位于 `x=6.45`；`x≈3.34..5.12` 是模型墙体外侧、不得进入的废弃条带，不能再为它切出碰撞开口。

## 走廊追逐（已实现第一版，待完整实机调参）

## 1. 关卡定位

白沙不是普通宿舍搜索房，而是第二章的完整动作关：

`白秋楼下警告 → 216 寝室搜证 → 宿舍异变 → 开门诱导 → 红光长影现身 → 第一次跳脸 → 玩家三次右转 / 鬼经白痕门抄近路 → 正常双门逃生或相遇后反向逃生 → 出口 → 3D 淡出并返回校园地图`

它承担三件事：

1. 把林伟死亡从“外部案件”拉回张超最熟悉的私人空间，让日常生活第一次彻底崩坏。
2. 给出旧论坛、苏婉、1953、地下仓库、张一诚/临湖餐厅的下一段调查方向。
3. 教会玩家室内追逐的规则：鬼不必比玩家快，也能靠白痕门捷径制造一次路线相遇；玩家需要根据鬼是否已经赶到改变逃生方向。

追逐鬼不能直接等同于苏婉。现行总剧情规定苏婉是警告和保护学生的守护灵，因此白沙追逐者建议定义为陈九/千绳会利用红绳阵与恐惧塑造的“红光长影”或“绳傀”。它可以借用苏婉传说吓人，却不能破坏后续“苏婉不是凶手”的反转。

## 2. 剧情口径与现有资料冲突

### 2.1 老照片

用户新版玩法要求宿舍内随机搜索“苏婉老照片”；仓库总策划则明确规定真正的 1953 老照片应由苏婉在后续医学院留下，避免宿舍和医学院重复掉落同一核心证物。

推荐口径：

- 白沙桌面找到的是**林伟从旧论坛打印/翻拍的 1953 照片副本**，正面人物被水渍或划痕遮住，背面只有“23:47”和临湖餐厅坐标。关内 UI 可称“旧照片翻拍件”或“受潮照片副本”。
- 它触发白沙剧情和追逐，但不授予终局道具 `photograph`；只设置 `foundBaishaPhotoCopy`，并解锁论坛/日记证据。
- 医学院由苏婉留下的才是**原件**，补全姓名、1953 身份和终局媒介能力，正式授予 `photograph`。

如果最终坚持宿舍直接获得真品，则必须同步改写医学院：苏婉不再掉落第二张照片，而是触碰并显影玩家已有照片背面的完整警告。两种口径必须二选一，不能让同一个 `photograph` 重复获得。

### 2.2 护身符与能量饮料

- 护身符应由白秋在楼下亲手交付，承接她的家族往事和羁绊线；不应在宿舍或图书馆随机掉落第二枚。
- 白沙能量饮料是追逐准备资源。建议拾取时设置持久关卡标记 `baishaEnergyBoost`，本次追逐速度从约 `3.33 m/s` 提升到 `3.7 m/s`。不要仅依赖当前可消耗的 `energy` 背包项，否则玩家喝掉后道具消失会让追逐速度逻辑反复变化。
- 未拾取饮料仍必须可通关，区别是容错更低、体力衰减更明显，而不是必死。

### 2.3 旧版梦境惊吓的融入

旧 HTML 的核心宿舍段是林伟空床、入睡后耳边一句“你在找我吗？”以及醒来时房间无人；总策划新增敲窗、湿脚印和电脑黑屏反射。新版关卡不宜再让玩家真的睡一觉打断节奏，可把这些元素压缩进探索阶段：

- 检查林伟床铺，确认三日前的噩梦记录和摔坏眼镜的同款盒。
- 窗外三次敲击；拉帘后只见玻璃外侧的湿脚印。
- 电脑自行亮起，旧论坛滚到“苏婉”时黑屏一闪，反射里林伟坐在空床上。
- 耳边出现一次“你在找我吗？”，但不立刻跳脸；真正第一跳脸留到玩家出门并看见红光长影时。

这样保留原文意象，又不抢走追逐启动的主惊吓。

## 3. 空间与动线

方向以用户俯视标注图为准，不用屏幕朝向或 GLB 原始轴向替代策划方向。

### 玩家正常路线

方向以用户标注图中的实际奔跑方向为准：

`寝室门 → 主走廊直跑到尽头 → 右转① → 直走 → 右转② → 直走 → 右转③ → 最后直道 → 三角形判定角 → 两个门洞 → 真出口`

玩家不进入带白色痕迹的门。图三正方形标记的能量饮料位于玩家路线中，允许靠近自动拾取，也允许按 `E` 提前拾取。

### 鬼的白痕门捷径

`寝室外展示点 → 沿玩家路线追赶 → 到达带白色痕迹的门 → 进入白痕门 → 穿过内部捷径 → 从玩家后续路线的相遇点出现`

带白色痕迹的门是鬼的固定捷径，不属于消失门组，整个追逐过程中保留视觉实体。玩家不可使用这条捷径；鬼只能从已标定的白痕门入口进入，不能穿过其他普通门或墙。

### 消失门组

需要在玩家到达图二三角形角落后同时完全消失的两道门是：

1. 带白色痕迹门右侧、离寝室更近的那一道门。
2. 上述门正对面的那一道门。

两门的门板、门把手、附着装饰和碰撞必须原子移除，表现与寝室门消失一致。带白色痕迹的捷径门本身不能被误删。

### 结果 A：NORMAL_ESCAPE

玩家速度足够快，在鬼从捷径出现前通过相遇区。玩家继续进入最后直道，在三角形判定角触发消失门组，连续穿过两个门洞后到达真出口。

### 结果 B：REVERSE_ESCAPE

玩家速度较慢，鬼通过白痕门捷径后在相遇区赶到。该次相遇迫使玩家反向逃生，并使真出口的门完全消失、开放通路。玩家必须立刻沿与鬼相反的方向折返，沿图三黑色反向路线绕回同一个真出口；不存在第二个“备用出口”。鬼不会切换为一条写死的反向路线，而是继续根据玩家实时位置沿合法走廊追赶。

“路线相遇”只负责给予玩家转身窗口；“实际抓捕”仍应是更近距离、无遮挡的独立死亡判定。两者不得共用一个距离阈值，否则玩家刚看见鬼就会直接死亡，无法执行反向逃生。

  └─ 选择“重新开始游戏” → 播放既有简短重启段落并从农医馆重新开始

核心约束：

- 剧情弹窗、跳脸和场景转场期间，鬼不得抓人。
- 路线相遇区用于决定玩家是否反向逃生，不等同于死亡抓捕；抓捕必须同时满足同走廊段、无遮挡、近距离阈值、非出口状态。
- 鬼的开局强制经过 B-D02 白痕门及其内部捷径；抵达捷径出口后，按玩家实时位置在已标定的合法走廊图上持续重算路线。道路图只包含可行走中心线和真实门洞，不允许穿过其他门或墙体。
- 追逐开始跳脸与死亡抓捕跳脸都走统一 `JumpscarePipeline`，每个事件持有幂等标记，避免声音、图片、文字重复或缺失。
- 抓捕顺序固定为：暂停移动和鬼状态 → 跳脸 → 全屏震动 → 死亡文字 → 2.5D 同款死亡选择框。
- 失败检查点设为电脑剧情完成、寝室门已经消失但玩家尚未出门的状态。选择“复活”后重置饮料、鬼位置、捷径进度、相遇分支、消失门组、真出口门和跳脸标记，不重播照片、阳台和论坛剧情。
- 追逐启动跳脸结束后的第 1 秒鬼不移动，第 2–3 秒按 50% 速度移动，第 4 秒起恢复全速。捷径口相遇时另给玩家 1 秒不可抓捕的转身时间，并让鬼在相遇后的 2 秒内保持 50% 速度。

## 6. 速度、体力与灯光

### 速度

- 当前宿舍蓝图冲刺速度是 `3.7 m/s`；追逐开始后，玩家向前移动会自动进入奔跑状态，不要求额外按住未提示的 `Shift`。
- 未取得饮料：追逐速度乘数 `0.9`，约 `3.33 m/s`。
- 已取得饮料：追逐速度 `3.7 m/s`。
- 体力耗尽后先稳定步行恢复到 `24` 点再重新自动奔跑，禁止在极低体力下逐帧切换跑/走状态；拾取饮料立即结束恢复状态。
- 鬼固定约 `2.78 m/s`（玩家满速的 `0.75`），压迫来自捷径和截击。
- 未取得饮料的体力下降可以更明显，但必须保留一条可通关时间窗。
- 能量饮料靠近自动拾取，也接受 `E`；追逐开始后侧边道具栏显示待拾取槽，拾取时沿用实体道具提示并显示“体力恢复 · 移动速度提升”，随后槽位标记“加速中”。拾取后立即恢复 30 点体力并设置本关持久标记 `baishaEnergyBoost`。即使拾取时体力已满，速度增益仍然有效。

### 灯光

- 寝室：弱红顶灯周期闪烁，不长时间全灭。
- 走廊：玩家已经经过的灯全部保持亮着；未经过区域只保持玩家逃生方向前方三盏灯亮，更远处维持黑暗。灯管不闪烁。
- 离开寝室时只点亮左侧段，先完成视觉诱导，再开始跑灯序列。
- 鬼带强红色发光，但发光不能穿墙暴露其捷径全过程。

## 8. 当前模型与仍缺内容

已确认 `baisha.glb`：

- 文件约 78.1 MB，包含 824 个对象、439 个网格、109 个材质、84 张内嵌纹理。
- 没有动画、相机或灯光；节点大多是通用导出名，尚无可直接绑定的语义锚点。
- 模型有四床寝室、外部走廊/岔路和楼梯等基础空间；当前仅完成主体视觉接入与临时安全出生视角。

第一版运行时已经具备语义锚点、门组、路径、能量饮料和单一真出口。要达到最终美术/发行质量，仍缺或需确认：

1. **瘦长鬼影追逐动画**：当前用完整静态人物模型做路径平移与转向；仍缺跑动、转弯、穿门和抓捕动画，并需要确认最终使用授权。
2. **白沙专属跳脸图或 3D 近景**：第一版复用场景一第二次跳脸资源；最终需要白沙瘦长鬼影专属画面，不能长期用图书馆资源冒充。
3. **专属音频**：现有通用音效可完成原型；最终仍缺追逐循环、鬼脚步/呼吸、白痕捷径穿门、相遇转向和抓捕死亡声桥。
4. **走廊灯与双分支调光**：灯位已覆盖玩家路线，但仍需分别跑通正常和反向路线，检查前方三灯规则、鬼红光遮挡和转角可读性。
5. **移动端/发布资源**：78.1 MB 主模型没有 LOD；上线前仍需完成 R2 同步、缓存版本号和移动端性能实测，且不得以未经视觉 QA 的降质换性能。

## 9. 已锁定的最终规则

1. **真出口**：就是白痕门右侧近寝室门与其正对面门组成的消失门组；门板/把手/碰撞完全消失后玩家穿过两道门离开。
2. **相遇缓冲**：捷径口相遇锁定反向逃生，给 1 秒不可抓捕转身时间，鬼同时降至 50% 速度 2 秒。
3. **追逐开局**：启动跳脸结束后鬼先静止 1 秒，再以 50% 速度跑 2 秒，从第 4 秒开始全速。
4. **死亡选项**：有符纸或复活次数时显示“复活”和“重新开始游戏”；复活优先消耗符纸，否则消耗一次复活，并回到论坛完成后的寝室门内检查点。无资源时只显示“重新开始游戏”。整局重开播放既有简短重启段落并回到农医馆。
5. **外景衔接**：穿过真出口回到 2.5D 校园地图，论坛日记进入背包，下一目标为临湖餐厅/张一诚。

1. 本地进入白沙后出生在四床寝室可行走区，主体 GLB 加载成功，控制台无模型/纹理 404。
