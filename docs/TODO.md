## 二、重新设计核心玩法

### 2.1 新的核心循环

玩家每进入一个建筑，都经历下面的循环：

```text
观察环境 → 找到可疑物 → 近距离检查 → 记录线索
       → 组合/判断线索 → 场景发生变化 → 躲避或逃离
```

- [ ] `P0` `[策划]` 写一页核心玩法说明，明确玩家一分钟内主要在做什么。
- [ ] `P0` `[程序]` 增加中央准星和统一交互检测，不再依赖踩进圆形触发区。
- [ ] `P0` `[程序]` 统一 `E` 键交互：查看、拾取、开门、使用机关都走同一套接口。
- [ ] `P0` `[程序]` 增加物品近距离检查模式：拾起后可旋转查看，发现背面文字或特殊标记。
- [ ] `P0` `[程序/策划]` 增加线索记录页，显示已发现线索、来源地点和简短描述。
- [ ] `P0` `[策划]` 每个场景设计 3～5 个有效线索，其中至少一个需要观察而不是直接拾取。
- [ ] `P1` `[程序/策划]` 增加简单的线索组合：选择两条相关线索，得出一个新结论并解锁后续路线。
- [ ] `P1` `[程序]` 增加检查点：进入建筑、完成关键谜题后自动保存，死亡不必从头开始。

### 2.2 理智系统改造

现在的理智更像一条血量。新版要让它改变玩家看到和听到的内容。

- [ ] `P0` `[策划]` 定义三档理智状态：正常、动摇、濒临崩溃。
- [ ] `P1` `[程序]` 理智下降后随机出现假脚步、灯光闪烁、错误门牌和远处人影。
- [ ] `P1` `[程序]` 假象不能挡住关键道路，也不能让主线道具永久消失。
- [ ] `P1` `[程序/音效]` 理智越低，呼吸、心跳和环境噪声越明显，但音量必须可以调节。
- [ ] `P2` `[策划]` 某些低理智状态可以看见正常状态看不到的隐藏线索，形成风险与收益。

### 2.3 敌人、躲避和追逐

- [ ] `P0` `[策划]` 明确敌人规则：什么情况下出现、如何发现玩家、玩家如何脱身。
- [ ] `P1` `[程序]` 先实现视线和距离检测，不做复杂战斗系统。
- [ ] `P1` `[程序]` 增加可躲藏位置，例如厕所隔间、宿舍柜子、舞台幕布后。
- [ ] `P1` `[程序/音效]` 玩家奔跑、开门和撞倒物品会制造声音，吸引敌人靠近。
- [ ] `P1` `[策划]` 每场追逐控制在 30～90 秒，路线提前经过测试，不能靠空气墙强行限制。
- [ ] `P2` `[程序]` 敌人丢失玩家后进入搜索状态，而不是一直精确知道玩家位置。

### 2.4 道具系统改造

- [ ] `P0` `[策划]` 删除只增加数值、但对玩法没有影响的重复道具。
- [ ] `P0` `[策划]` 保留手电筒、门禁卡、照片、日记残页等与剧情和场景有关的物品。

## 三、Blender 与 Three.js 场景生产流程

### 3.1 场景规范

- [ ] `P0` `[建模/程序]` 统一 Blender 单位为米，人物眼高按 1.6 米测试。
- [ ] `P0` `[建模]` 统一模型命名：
  - `VIS_`：玩家能看到的模型。
